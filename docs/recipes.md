# 配方与流程模式

这里给出几类常见自动化的建图方式。所有配方都只使用公开的 ADB / scrcpy 操作，请在自己有权操作的设备和账号上使用。

## 通用建议

1. **一个节点只做一件事**：进入页面、选择选项、确认、发送，分别建节点。
2. **检测重点放在稳定区域**：标题、消息气泡、按钮文字区域，不要框住会滚动或变化的时间、广告。
3. **阈值先保守**：0.88 起步；截图差异大时降到 0.82–0.86，并用保底兜住。
4. **一个状态可以有多个下一步**：用连线权重表达偏好，或用加权随机。
5. **先模拟运行**：勾选「模拟运行（不点击手机）」观察候选和得分，再真机执行。
6. **长跑关闭截图保存**，避免占满磁盘。

## 每天点外卖

### 结构

```
[外卖首页] ──→ [餐厅 A] ──→ [选菜页] ──→ [提交订单]
      │
      ├──→ [餐厅 B]
      └──→ [餐厅 C]
```

- 首页节点：检测重点框住底部“点餐/首页”区域或顶部定位。
- 餐厅节点：检测重点框住餐厅名，避免不同餐厅页面因为背景相似而误判。
- 从首页到多个餐厅的连线权重设为 1。
- 在「保底 / 运行参数」里选择「加权随机（每天换一家）」，这样多个餐厅都达标时会随机选。
- 如果只想固定常点，选择「最相似优先」，把常点餐厅的连线权重调高。

### 建议动作

- 首页 → 点击“点餐”按钮；
- 餐厅 → 点击目标菜品；
- 选菜页 → 点击“去结算”；
- 提交页 → 点击“提交订单”（建议保留一个人工确认步骤，避免误下单）。

### 保底

```
返回 back -> 等待 1s -> 再返回
```

若是支付/提交环节，建议把 `max_fallbacks` 设小，失败就停止而不是乱点。

## 每天吃什么（随机选择）

结构：

```
[选择页] ──→ [结果 A]
      ├──→ [结果 B]
      └──→ [结果 C]
```

- 选择页作为入口。
- 结果节点可以是不同外卖、食堂窗口或菜单页面。
- 选择「加权随机」，权重表达偏好；相似度余量也会影响随机权重。
- 每次结果都写入历史记录，方便回看。

## 不同已知消息自动回复

### 结构

```
[聊天列表] ──→ [消息 A 画面] ──→ [输入回复 A] ──→ [发送]
        ├──→ [消息 B 画面] ──→ [输入回复 B] ──→ [发送]
        └──→ [消息 C 画面] ──→ [输入回复 C] ──→ [发送]
```

- 消息节点：检测重点框住联系人名 + 消息气泡；不要框住时间戳。
- 输入回复：动作类型选「输入文本」。
- 发送：单独的“发送按钮”截图节点，点击点放在发送按钮上。
- 未知消息不命中时执行保底：返回聊天列表 / 等待 / 停止。

### 中文输入

Android `adb shell input text` 对 Unicode 支持依输入法而定。批量中文回复建议：

1. 安装 ADBKeyboard；
2. 在手机上切换为 ADBKeyboard；
3. 用 `input text` 发送中文；
4. 回复后切回原输入法。

也可以在手机端使用剪贴板方案，但不同系统版本差异较大。

## 多分支与状态偏好

同一个状态可以连出多条边：

| 连线 | 权重 | 含义 |
| --- | --- | --- |
| 首页 → 常点餐厅 | 5.0 | 最常选 |
| 首页 → 新餐厅 | 1.0 | 偶尔尝试 |
| 首页 → 搜索 | 0.2 | 前面都不可用时 |

运行时会先按相似度过滤，再按 `similarity + β × weight` 排序。权重不是硬编码顺序，而是“在都看得像时更偏向谁”。

## 需要人工确认的场景

支付、删除、发送给重要联系人等不可逆操作，建议：

- 把最终确认节点单独建；
- 在运行模式先模拟，核对候选；
- 或者流程在“确认页”停止，人工点最后一下；
- 保底次数设小，出错即停。

## 调试技巧

- 运行模式会显示每个候选的“综合相似度 / 检测重点相似度 / 路径偏好 / 最终得分”。
- 如果目标节点排在第二，检查：
  - 检测重点是否框住稳定区域；
  - 是否被其他相似节点抢走；
  - 连线权重是否太低；
  - 阈值是否过高。
- 历史记录里每一步都有截图，可直接双击查看当时画面。
