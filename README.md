# scrcpy-flow
This project uses Android USB ADB or scrcpy to capture the screen and enable mind-controlled interaction.
# scrcpy-flow
用手机截图驱动 Android 自动化的桌面工具：**图片状态识别 + 流程图 + 状态偏好 + 保底机制 + scrcpy 控制**。
适合把“每天点外卖”“自动选择今天吃什么”“已知消息自动回复”这类重复操作，做成可编辑、可导出、可迁移的流程。
> 无设备也能先做流程：编辑模式支持导入截图、设置点击点、框选检测重点、连线和模拟运行。运行模式通过 scrcpy / ADB 截图与点击手机。
## 现代工作区（默认）
使用 PySide6/Qt 重写了界面，外观和操作接近 VS Code / PS：
- 深色主题、可停靠/浮动的面板、中央标签页、命令面板（`Ctrl+Shift+P`）。
- 左侧工作区、右侧属性、底部控制台都是 dock，可拖出为独立窗口。
- 三档界面可按使用深度切换，共享同一套流程、工程和设置。
- 菜单「视图 → 独立运行窗口」可以把运行面板单独拉出来。
### 三个界面版本
- **简洁版**：只看区块顺序与运行，适合日常使用。
- **普通版（默认）**：完整流程画布、节点属性、素材库、历史和控制台。
- **专业版**：普通版全部功能 + 「专业工具」标签页，包含批量设备、智能定位（控件树 / OCR）和录制回放。
可在工具栏右侧「界面」下拉框或「视图 → 界面模式」中切换。
```bash
./install2.sh     # 安装 PySide6 版依赖
./run2.sh         # 启动现代工作区
```
Windows 使用 `install2.bat` / `run2.bat`，macOS 使用 `install2.sh` / `run2.sh`。经典 Tkinter 界面仍然保留：
```bash
python -m scflow --classic
```
## 功能
- **极速连滑 / 连点（100+ 次/秒）**：新动作类型「极速连滑/连点（100+ 次/秒）」，用 Android 自带的 monkey 在设备内单进程注入，实测 100 次约 1 秒（约 95~105 次/秒），200/300 次更快；起终点填相同坐标就是连点；次数、起终点、每次时长都能在检查器里改。
- **加速运行**：「运行」页只有 普通 / 快速 / 极速 三档，一键切换；滑动节点要连滑几次，在节点检查器的「重复次数」里设置（合并成一条 adb 命令批量发送），用于快速连滑/刷屏。
- **云端 AI 助手**：底部新增「AI 助手（云端 API）」面板，选「快速配置」里的常见服务（DeepSeek / OpenAI / 通义 / 本地 LM Studio / Ollama 兼容），填 Key 即可用；「AI 后端」默认「自动」（配了云端就优先云端，否则用本地）。高级功能开关收在「高级选项」里。
- **AI 自动创建项目**：AI 对话框新增「多区块项目」模式，一句话生成 1~4 个区块（每个区块一条流程）并自动串成可运行项目。
- **人工介入**：运行时点「人工选择」→ 弹窗选 点击/按键/打开应用/滑动/输入/等待；可勾选「记住」把动作写入流程画布（可在画布/检查器里编辑删除），下次匹配失败时作为保底动作；可勾选「检测是否完成」，不达标可重新人工选择或让 AI 托管。
- **三档界面**：简洁版 / 普通版 / 专业版，按使用深度切换，不影响已有数据。
- **本地 AI（Ollama）**：接入本机 ollama 的视觉模型，用“看截图 + 读控件树”驱动自动化：
  AI 决策节点（不截任何图也能跑）、图片匹配失败时 AI 接管、相似度不足时 AI 选节点、一句话生成流程。
  全部离线推理；关掉 AI 后行为与纯图片流程完全一致。
- **两套模式**
  - 运行模式：按流程或区块项目自动截图、匹配、点击、记录状态与结果。
  - 编辑模式：导入图片、画流程图、设置点击位置、检测重点、偏好权重和保底步骤。
- **专业版：批量设备**：勾选多台已连接设备，并发运行同一项目或流程，按设备分别记录日志，可随时停止。
- **专业版：智能定位**：通过 Android 控件树（uiautomator）或可选 OCR 找到文字/按钮，测试点击或写入当前节点；控件树定位会作为点击首选，失败自动回退图片识别。
- **专业版：录制回放**：在受控 scrcpy 窗口中操作手机，自动把每次点击和点击前画面录制成流程节点并连成流程（实验功能，需要 pynput）。
- **专业版：录制后编辑**：停止录制后可调整节点顺序、名称、点击位置、动作和等待时间，支持删除、设入口、转到属性面板完整编辑，并自动重新连线。
- **导出手机文件**：文件菜单可导出 `.scflowpkg` 手机流程包（含流程、图片、动作、控件选择器和入口信息）。
- **手机 APK 运行**：使用 `flow-to-apk-sdk/phone-runner` 把 `.scflowpkg` 构建成独立 APK，或安装通用运行器后在手机上导入运行。
- **区块项目**：每个流程就是一个区块；大画布中拖动排序，按顺序执行或交给 Python 编排。
- **Python 编排**：区块名自动成为可调用变量，可写 `if` / `while`，支持自定义变量、`log`、`sleep`、`stop`。
- **撤回**：流程画布和区块项目各有撤回按钮，覆盖节点、连线、ROI、顺序、变量、脚本等编辑。
- **取消连接/下一步**：选中一条连线后一键删除，不需要进弹窗。
- **成分相似度匹配**：侧重点检测节点使用 `s = W1·MR + W2·MR非`，侧重检测节点使用 `s = W·MR`（W=1）；
  成分由颜色、纹理、结构、边缘组成，可在「相似度编辑」中调整并预览。旧的混合向量仍保留用于兼容/回退。
- **检测重点（ROI）**：在截图上框选一个区域，该区域相似度按权重参与最终判断，默认占主导（0.72）。
- **相似度编辑标签页**：为节点设置匹配阈值 r 和颜色/纹理/结构/边缘成分权重；
  侧重检测节点固定 W=1（s=W·MR），侧重点检测节点使用 s=W1·MR+W2·MR非；
  支持成分锁定、自动平衡、成分预览、点击预览图放大、放大窗口「选框不可视」开关、
  载入本地图片/手机当前画面计算得分；结果同时显示「检测对象得分」和「点击对象得分」；
  手机当前画面支持「模拟运行」和「观测点击点」（显示 OpenCV 检测框，可用「选框不可视」隐藏），并提供「清理测试缓存」；
  可为颜色/纹理/结构/边缘分别设置成分匹配阈值，低于阈值时动作不执行并提示动作相似度低；
  框选点击对象与相对点击共用点击对象成分权重；
  MR/MR非/点击对象的权重仍在，只是不再单独显示预览框。
- **取相对点击点**：设置相对点击后会显示该按钮，在状态图片上点一下即可把偏移 X/Y 同步到偏移面板，
  偏移点用绿色圆圈标记。
- **可缩放状态图片**：编辑区支持按钮缩放、Ctrl+滚轮缩放、中键拖动平移，便于精确框选。
- **重点点击对象**：在状态图片上框选要点击的对象；运行时会识别该对象当前位置并点击其中心。
- **不模拟点击**：状态图片下方的开关，一键把节点设为“仅识别状态、不点击”。
- **启动应用 / 清空输入**：动作支持冷启动指定包名；文本动作可先清空输入框并自动回车，适合电商搜索框。
- **流程自动排版**：节点都在同一位置时自动按入口向下排版；也可以手动「自动布局」。
- **直接打开项目**：`--open-project` / `--open-flow` 启动界面即定位到指定区块项目或流程。
- **状态偏好**：每个步骤可以有多个“下一步”，连线权重就是不同状态下的偏好；可加“加权随机”让每天自动换一家。
- **严格下一步匹配**：默认只比较当前状态和它的直连下一步；未到步骤的节点及其检测重点不参与计算，避免提前误触。也可切换为“可达节点”或“全局匹配”。
- **保底机制**：连续未匹配时自动降阈值重试，仍失败则执行“返回 / 等待 / 滑动 / 点击 / 输入”等保底步骤。
- **完整日志**：每次操作后记录当前状态、匹配节点、相似度、动作、结果和截图。
- **流程导入导出**：图片随流程打包为单个 JSON 文件；导入时可人工选择上游、下游节点进行衔接。
- **手机截图建节点**：在编辑模式一键抓取手机当前画面并生成步骤。
- **跨平台**：Linux、Windows 与 macOS 均可运行；数据、图片、截图都在程序旁边的 `data/`，复制文件夹即可迁移。
- **双 UI**：Qt 现代工作区 + 经典 Tkinter；数据库与 tools 完全共用。
- **可模拟运行**：不点击手机，只看候选匹配与下一步可能性，适合低配电脑或调试阶段。
## 本地 AI：让流程更通用
图片流程要求“每个画面都先截过图”，遇到没截过的页面就卡住。接入本机 Ollama 后，程序多了一条“看得懂屏幕”的路径：
| 能力 | 说明 | 适用场景 |
| --- | --- | --- |
| **AI 决策节点** | 节点只写一句目标，运行时模型看当前截图 + Android 控件树，逐步点击/输入/滑动，完成后自动走向下一个节点 | 新流程、页面常变、不想逐页截图 |
| **失败接管** | 图片匹配重试失败后，让模型按流程目标救场一步，再回到原流程 | 弹窗、广告、改版页面 |
| **节点重排** | 相似度都不到阈值时，把候选节点交给模型挑一个 | 多个页面长得很像 |
| **一句话生成流程** | 描述需求，模型拆成 1~6 个 AI 步骤并直接建好流程 | 快速起步 |
全部推理都在本机完成，截图不会上传到任何服务器。
### 1. 准备 Ollama 与视觉模型
```bash
# 安装 Ollama：https://ollama.com/download
ollama serve                    # 桌面版通常已自动运行
# 能看图的模型，任选其一；3B~7B 在普通电脑上就能跑
ollama pull qwen2.5vl:3b        # 推荐：小、快、中文好
ollama pull llava:7b            # 备选
ollama pull qwen3.5:4b          # 支持看图 / 工具调用 / 思考
```
程序会从 `/api/tags` 与 `/api/show` 自动挑选第一个支持 `vision` 的模型，通常不需要手动填。
检查当前状态：
```bash
python -m scflow --ai-status
```
### 2. 在界面里启用
- 菜单「AI」→「AI 设置…」：确认地址 `http://127.0.0.1:11434` 与视觉模型，按需调整截图尺寸、超时和功能开关。
- 底部「AI 助手」面板（与「输出」同一组标签）：刷新状态、分析当前画面、直接执行一句 AI 任务。
- 流程画布 →「添加 AI 节点」，填一句目标即可；右键节点可「编辑 AI 目标…」。
### 3. 不建流程也能跑
```bash
python -m scflow --ai-task "打开设置，查看电池电量" --no-scrcpy
```
程序会循环：截图 → 读控件树 → 模型给一个动作 → 执行，直到模型说完成或达到 `--steps` 上限。
### 4. 配置与开关
设置保存在 `data/ollama.json`（跟着工程目录迁移），也可以用环境变量覆盖：
| 变量 | 作用 |
| --- | --- |
| `SCFLOW_OLLAMA_URL` | 服务地址，默认 `http://127.0.0.1:11434` |
| `SCFLOW_OLLAMA_MODEL` | 视觉模型名 |
| `SCFLOW_OLLAMA_TEXT_MODEL` | 生成流程用的文本模型 |
| `SCFLOW_OLLAMA_TIMEOUT` | 单次请求超时秒数 |
| `SCFLOW_OLLAMA_DISABLE=1` | 完全关闭 AI，回到纯图片匹配 |
### 5. 效果与限制
- **目标写成动作，不要只写结果**：「点击底部「电视台」标签」「在搜索框输入黄焖鸡并回车」比「进入电视台页面」「买好外卖」可靠得多；结果类描述容易让模型反复点击或误判完成。详见 [`docs/ollama.md`](docs/ollama.md#怎样写好-ai-节点的目标)。
- 4B 级模型在普通 CPU 上单次决策约 1~5 秒；截图最长边默认 720px，调小更快。
- 模型输出相对坐标（0~1）；有控件树时优先点击控件中心，精度明显更高。
- 纯文本模型（如 `gemma:2b`）不能看图，程序会提示换模型。
- 中文输入仍受 `adb shell input text` 限制，建议安装并启用 ADBKeyboard。
- AI 只是“多一条路”：原有图片流程、连线偏好和保底机制不变；关闭 AI 时行为与旧版一致。

## 快速开始
### 依赖
- Python 3.10+
- Android 设备已开启 USB 调试
- [scrcpy](https://github.com/Genymobile/scrcpy) 与 `adb`
- 可选：[Ollama](https://ollama.com) + 一个视觉模型（如 `qwen2.5vl:3b`），用于 AI 决策节点与智能兜底；不装也能正常使用全部图片流程
- Linux 额外建议安装 `xdotool`（scrcpy 窗口输入会用到；没有则自动回退 ADB 输入）
- macOS 建议使用 Homebrew 安装 `android-platform-tools` 与 `scrcpy`；scrcpy 窗口输入可选安装 `cliclick`
### 安装
```bash
git clone <your-repo-url> scrcpy-flow
cd scrcpy-flow
./install2.sh        # 2.0（PySide6 + 核心依赖）
# 或只用经典界面：
# ./install.sh
```
`requirements.txt` 已包含 OpenCV，用于「重点点击对象」的模板定位。若只安装核心依赖（numpy / Pillow / mss），其他功能仍可用，但重点点击对象会退化为相对位置点击。
专业版工具需要额外依赖：
```bash
pip install -r requirements-pro.txt
# OCR 还需要系统 tesseract：
# macOS: brew install tesseract tesseract-lang
# Linux: sudo apt install tesseract-ocr tesseract-ocr-chi-sim
# Windows: 安装 Tesseract-OCR 并加入 PATH
```
`pynput` 用于录制回放；macOS 需要辅助功能权限，Linux 需要 X11 会话（Wayland 下可能无法录制全局点击）。
Windows:
```bat
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```
macOS:
```bash
brew install android-platform-tools scrcpy
./install2.sh
# 可选：scrcpy 窗口点击更稳定
brew install cliclick
```
也可以直接执行 `./install.sh` 或 `install.bat`。
### 启动
```bash
./run2.sh         # Linux / macOS 现代工作区
./run.sh          # Linux / macOS（经典界面依赖检查）
run.bat           # Windows
```
或：
```bash
python -m scflow
```
首次启动会创建 `data/`：
```
data/
├── scflow.db        # 流程、节点、连线、运行记录
├── images/          # 节点截图
├── screenshots/     # 运行时截图
└── exports/         # 默认导出目录
```
把整个项目文件夹（含 `data/`）复制到另一台电脑即可迁移。
### 便携工具
开源仓库不包含 `adb` / `scrcpy` 二进制，避免仓库体积过大：
- macOS：`brew install android-platform-tools scrcpy`
- Linux：使用发行版包管理器，或把工具放到 `tools/linux/`
- Windows：把 `adb.exe` / `scrcpy.exe` 放到 `tools/windows/`
- 程序会自动搜索 `tools/`、系统 PATH、Homebrew / MacPorts / Android SDK 常见路径，也支持 `SCFLOW_ADB` / `SCFLOW_SCRCPY` 覆盖。
程序启动时会自动递归搜索 `tools/` 下当前平台的可执行文件，优先使用内置版本；找不到才回退系统 PATH。也可以用 `SCFLOW_ADB` / `SCFLOW_SCRCPY` 环境变量覆盖。
> 从 Git 仓库拉取时，`tools/` 下的二进制会被 `.gitignore` 排除，需要按 `tools/README.md` 重新下载。
## 使用流程
### 1. 编辑模式：区块项目（可选）
1. 顶部切到「区块编排（项目）」。
2. 「新建项目」。
3. 在左侧「区块库」选中一个流程，点「添加为区块」。
4. 在大画布中拖动卡片排序，或用上移/下移。
5. 选择「按区块顺序执行」或「使用 Python 编排」。
6. Python 模式中，区块名就是变量，例如：
```python
if 首页():
    点餐()
while 次数 < 3:
    选菜()
    次数 += 1
```
7. 「变量」表可添加初始值；「生成顺序脚本」会按当前顺序生成模板。
8. 「保存项目」后，运行模式的「运行对象」里会出现这个项目。
### 2. 编辑模式：搭一个区块
1. 顶部切到「流程画布（区块内部）」，左侧「新建」流程。
2. 「添加节点」导入一张手机截图；或点「手机截屏建节点」直接抓当前画面。
3. 在图片上：
   - 「取点击点」：点一下要按的位置。
   - 「框选检测重点」：拖一个区域。**该区域相似度默认占 72% 权重**，可通过「检测重点权重」调整。
   - 「框选重点点击对象」：框住按钮/菜品/发送键等目标。运行时会用 OpenCV 在当前画面中定位该对象，并点击它的中心；定位失败时回退到相对位置。
   - 「框选相对点击」后，「查看」会变成「取相对点击点」，可直接在状态图上设置偏移点击点。
   - 「相似度编辑…」或右键匹配阈值：打开相似度编辑标签页调整 r 和成分权重。
   - 「不模拟点击」：仅识别状态，不执行点击。
   - 图片可放大、缩小、适应窗口；Ctrl+滚轮缩放，中键拖动平移。
4. 设置动作（点击 / 滑动 / 按键 / 输入文本 / 等待 / 无动作）。
5. 选中当前节点，点「连接 / 下一步」选择下一个节点。可以重复添加多个下一步，并给不同连线设置偏好权重。
6. 在「保底 / 运行参数」里设置重试次数、降阈值步长、保底步骤。
7. 「导出当前流程」得到单个 `.scflow.json`，图片已内嵌。
### 3. 运行模式：自动执行
1. 选择运行对象：`项目：xxx` 或 `流程：xxx`，以及设备。
2. 画面来源默认 `scrcpy 窗口`（失败自动回退 ADB 截图）；输入方式默认 ADB，也可切换 scrcpy 窗口输入。
3. 勾选「启动 scrcpy 窗口」可同时看到手机画面。
4. 首次调试建议勾选「模拟运行（不点击手机）」，观察候选和日志。
5. 点「开始运行」。
每一步会：
1. 截图；
2. 按匹配范围筛选候选：默认只比较当前状态及其直连下一步；未到步骤的节点及其检测重点不参与计算。可在流程设置中改为“可达节点”或“全局匹配”；
3. 加入当前状态的连线偏好，排序候选；
4. 命中阈值后执行该节点动作；
5. 记录状态、动作、相似度、结果和截图；
6. 连续未匹配时进入保底机制。
### 4. 导入并衔接
「导入」流程文件时可以选择：
- 新建流程；
- 合并到当前流程；
- 人工选择一个当前节点，连到导入流程的入口；
- 人工选择导入流程的出口，连到当前流程的某个节点。
## 三个典型玩法
### 每天自动点外卖（并换一家）
- 把外卖首页、不同餐厅页、确认页分别做成图片节点。
- 从“首页”连到多个“餐厅”节点，权重都设为 1。
- 运行设置里选择「加权随机（每天换一家）」。
- 多个餐厅都达到阈值时，会按偏好权重随机选一个。
- 保底步骤设置「返回」+「等待」，防止页面卡住。
### 自动回复不同已知消息
- 为每种已知聊天画面建立一个节点，检测重点框在消息气泡或标题区域。
- 动作设为「输入文本」，填入对应回复。
- 后续节点设为「发送」按钮的截图与点击。
- 未知画面不命中任何节点时，执行保底（返回 / 等待 / 停止）。
> Android 的 `input text` 对中文支持取决于输入法。批量中文回复建议安装 ADBKeyboard 并切换输入法。
### 每日选择吃什么
- 做一个“选择页”节点，后接多个“结果”节点。
- 用连线权重表达偏好，或启用加权随机。
- 每次运行都记录到历史记录，方便回看今天选了什么。
更多思路见 [`docs/recipes.md`](docs/recipes.md)。

## 架构
```
scflow/
├── config.py        # 便携数据目录、工具路径
├── db.py            # SQLite 存储：流程 / 节点 / 连线 / 会话 / 步骤日志
├── models.py        # 数据模型
├── embeddings.py    # 混合图片向量 / 可选 CLIP
├── vision.py        # 截图处理、模板定位、点击点映射
├── device.py        # ADB 与 scrcpy 窗口控制（Linux / Windows / macOS）
├── engine.py        # 匹配、偏好、保底、日志
├── ollama.py        # 本地 Ollama 客户端、模型能力探测、AI 设置
├── ai.py            # 看屏决策、节点重排、一句话生成流程、极简智能体
├── project_runner.py # 区块顺序 / Python 编排
├── undo.py          # 流程与项目快照、撤回栈
├── flowio.py        # 流程导入导出与人工衔接
└── gui/             # Tkinter 运行模式 / 编辑模式 / 历史记录
```
匹配分数：
```
普通节点：similarity = cos(截图向量, 节点向量)
重点区节点：similarity = roi_weight × cos(重点区) + (1 - roi_weight) × cos(全图)
最终得分：score = similarity + β × 当前状态到该节点的连线权重
```
详细设计见 [`docs/architecture.md`](docs/architecture.md)，流程文件格式见 [`docs/flow-format.md`](docs/flow-format.md)。

## Windows 说明
- 使用官方 Python 安装包（自带 Tk）。
- `adb.exe` / `scrcpy.exe` 放到 `tools/` 或加入 PATH。
- scrcpy 窗口截图使用 `mss`，窗口定位使用 Win32 API，不依赖 xdotool。
- 若 scrcpy 窗口输入异常，运行模式会自动回退到 ADB 输入。
## macOS 说明
- 推荐 Python 3.10+（Homebrew 或 python.org 安装均可）。
- 安装设备工具：
```bash
brew install android-platform-tools scrcpy
brew install cliclick   # 可选，scrcpy 窗口点击更稳定
```
- 默认使用 ADB 截图和 ADB 输入，不需要额外桌面工具即可运行。
- 如果选择 scrcpy 窗口截图/输入，需要在「系统设置 → 隐私与安全性」中允许终端或 Python：
  - **辅助功能**：读取窗口位置、模拟点击；
  - **屏幕录制**：截取 scrcpy 窗口。
- scrcpy 窗口在 macOS 上会以无边框方式启动，便于按窗口内容定位；权限不足或窗口控制失败时会自动回退 ADB。
- 程序会自动查找 Homebrew、MacPorts 和 Android SDK 常见路径下的 `adb` / `scrcpy`，也支持 `SCFLOW_ADB` / `SCFLOW_SCRCPY` 环境变量覆盖。
- 打包为 `.app` 后，数据默认写入 `~/Library/Application Support/scrcpy-flow/data`；从源码运行仍使用项目旁的 `data/`。

## 导出手机文件与 APK
1. 在 scrcpy-flow 中打开 **文件 → 导出手机文件…**，选择流程或项目，导出 `.scflowpkg`。
2. 在 `flow-to-apk-sdk/phone-runner` 中构建 APK：
```bash
cd /path/to/flow-to-apk-sdk/phone-runner
./build_flow_apk.sh /path/to/your.scflowpkg
./install_apk.sh build/your.apk
# 或构建并安装
./build_and_install.sh /path/to/your.scflowpkg
```
3. 也可以只安装一次通用运行器：
```bash
./build.sh
./install_apk.sh build/app-debug.apk
```
然后在手机里打开「scflow 手机运行器」→「导入手机文件」→ 选择 `.scflowpkg`。
手机端要求 Android 11+，首次使用需开启无障碍服务。独立 APK 的应用名、包名、版本号来自导出时填写的应用信息。
## 已知限制
- 图片节点默认按“整屏截图”设计；「重点点击对象」和局部裁剪图依赖 OpenCV 模板定位。未安装时点击会退化为相对位置。
- 重点点击对象在画面中找不到时，会回退到节点图片中的相对中心；如果目标位置变化很大，建议同时调整检测重点或使用更独特的对象截图。
- 中文文本输入依赖手机输入法；建议用 ADBKeyboard。
- scrcpy 窗口输入在 Linux 需要 `xdotool`，Windows 使用 Win32 API，macOS 优先使用 `cliclick` 或 System Events（需要辅助功能权限）。
- Python 编排只提供受限内置函数，但不是严格安全沙箱；请只运行自己的脚本。
- 纯 Python 的 `while True:`（不调用区块、不 sleep）无法用停止按钮中断；请使用 `max_block_runs` 与可中断的 `sleep`。
- 撤回栈只保存在内存中，关闭程序后清空。
- AI 决策依赖本地视觉模型的质量：4B 级模型偶尔会看错页面或点偏，重要流程建议先用「模拟运行」验证，并给节点设置合理的决策次数上限。
- AI 决策比图片匹配慢（每次 1~5 秒），且会持续占用 GPU/CPU；不建议用来替代高频、稳定的固定页面点击。
- AI 只看单帧截图和控件树，不读聊天记录、不登录账号；截图仅在本机内存/本地服务中流转。
- 匹配范围默认是「只匹配下一步」；如果流程依赖“从任意页面跳到某个公共页面”，请改成「全局匹配」或在流程图中补上对应连线。
- 不做验证码破解、风控绕过或平台规则规避；请只在合法、可控、自己有权操作的设备与账号上使用。
- 本项目通过公开的 ADB / scrcpy 接口操作设备，不修改任何第三方应用。
